# 研究方法与验收

## 研究问题

当任务是“搜集资料并完成一份有引用的行业分析报告”，五款消费端产品在研究、材料组织、修改与交付上的差异，会怎样影响选择？

研究采用目的性选样，覆盖不同工作流入口。并未根据市场份额抽样，因此不推断全市场排名。八个维度由同一任务拆解产生，全部产品采用同一框架；具体事实、套餐、原文和判断统一存放在 `data/research.json`。

## 证据处理

1. 从官方入口查找定价、帮助与功能说明，记录原始 URL、重定向后的 URL 和实际访问时间。
2. 静态页面提取正文；动态购买页使用浏览器加载，并分别记录月付和年付状态。
3. 保存适用入口、套餐、地区和计费条件；数值在事实文本或套餐记录中保留单位。未公开的限制不自行补值。
4. 摘取支持结论的原文，生成独立编号。每个比较单元格、推荐和价格记录引用相应编号。
5. 将采集正文的空白归一化后计算 SHA-256。检查 71 条摘录均能在对应指纹的原始采集正文中找到。
6. 检查摘录与结论语义是否对应。来源冲突按产品入口和时效裁决，保留处理理由。文本匹配证明转录一致，不能单独证明来源内容真实或产品效果。

地区没有统一为单一市场：美元与人民币分组，Google 价格明确使用美国入口，Kimi 采用中文购买页。页面可访问不意味着用户所在地区或账户必然可购买、使用所有能力。

## 三个会改变结论的案例

| 问题 | 处理 | 对选型的影响 |
|---|---|---|
| Kimi 购买页与帮助页套餐命名不同 | 当前报价采用购买页；旧任务配额不套到新名称 | 不能仅凭历史套餐任务数估算报告产量 |
| Claude 年价的页面折算经过取整 | 以年付总额除以 12，保留两位小数 | 对比月费前先区分承诺付款周期 |
| Perplexity 官方入口访问受限，应用内购金额缺周期 | 开发者描述用于对应能力；二手资料标历史；价格留空 | 当前价格不能进入同口径图表，购买前需补核 |

未知不是不支持。历史能力不作为当前确定承诺。官方引用功能说明不等于实测引用正确率。

## 分析如何形成

每条场景建议采用“观察 → 判断 → 选择与边界”。例如导出到 Docs、Word/PDF 或可编辑文件，会影响后续协作路径；据此给出候选工具，并不推断文本质量排名。产品机会的优先级属于研究者判断，附验证路径，不表示需求已经过用户访谈证实。

统一任务卡可在网站查看或下载，包含共同任务、记录项和评判口径。后续实际测试应记录账户套餐、地区、任务输入、时间、原始输出及逐条引用核查结果；本次不将任务卡当成执行记录。

## 工程验收记录

2026-09-27，使用本机 Chrome，在禁网的 `file://` 页面完成自动检查。脚本为 `scripts/check_browser.mjs`。

- 40 个比较项与证据弹窗均可打开；全部来源按钮解析成功。
- 产品筛选、工作环节筛选、空选择恢复与场景键盘切换正常。
- 年付折算、未知值保留及订阅预算计算符合已采集的价格口径。
- JSON 下载与原始数据一致；任务卡下载正常。
- 768、390、320 像素宽度无整页横向溢出；窄屏表格可滚动到末列，固定列不遮盖末列。
- 打印展开全部产品、场景与证据，打印后恢复之前的选择与计费状态。
- 页面无 JavaScript 异常、无远程网络请求。截图用于桌面与窄屏视觉复查，Chrome PDF 用于打印检查。

自动检查不能替代真实设备全覆盖或产品效果测评。`scripts/build.py --check` 校验引用关系及生成文件同步；`scripts/check_evidence.py` 在本地原始缓存存在时复核摘录转录。缓存缺失时会明确报告未完成，避免把结构检查当成再次访问了来源。

## 数据维护

公开交付保留必要原文摘录、链接、时间、范围和采集指纹；不打包第三方整站内容。购买前需重新查看官方页面。再次研究时应更新受影响的事实、引用及判断，而非仅修改图表数字。
